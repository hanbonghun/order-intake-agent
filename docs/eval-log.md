# 평가 개선 이력

각 항목은 "가설 → 변경 → 수치 변화 → 남은 실패"로 기록한다.
수치는 `uv run python -m evals.run --compare <이전> <이후>` 출력에서 옮긴다.

## v1 — 파서 + classify + extract (2026-10-17)
- 가설: 깨끗한 발주는 structured output 추출만으로 헤더 필드와 품목 구조를 거의 완벽히 얻을 수 있다
- 변경: 본문·PDF·엑셀 파서, classify(gpt-5.4-nano), extract(gpt-5.4-mini), identify_customer(이메일 조회 + 기본 배송지). 매칭·검증은 임시 노드
- 수치 (30건)
  - 분류 1.000, 거래처 1.000, 납기 1.000, 배송지 1.000
  - 품목 매칭 0 (임시 노드라 정상). 대신 trace의 추출 품목을 정답과 대조: **97개 중 97개 품목명·수량·단위 일치**
  - 평균 1,338 토큰, 2.5초, $0.001 / 건
- 모델 비교 (참고, 정식 기록 아님)
  - qwen3:8b (Ollama, M1 16GB): 3건 스모크 테스트에서 필드 전부 일치. 25건 진행 시점 평균 약 46초/건으로 중단
  - 느린 원인은 메모리 부족(스왑 15GB 사용). JSON 스키마 제약은 원인이 아니었다 (json_schema 6.8 tok/s > function_calling 3.8 tok/s)
  - → 개발은 API 모델로 진행하고, 로컬 모델 비교는 메모리 여유가 있는 환경에서 다시 측정
- 다음: match_products (별칭 정확 일치 + 단위 정규화 "box"→"박스" + 단위 환산)

## v4 — 발신자 미확인 검토 분기, 단위 동의어 (2026-10-17)
- 변경: 상호명으로만 식별하면 unverified_sender(내부 검토), 단위 동의어 사전(포→포대 등)

    - "서울우유"는 1·2위 차이 0.069 (일반 vs 저지방) → 점수만으로는 결정 불가, 거래처 주문 이력이 필요
  - → resolver는 점수 하나가 아니라 거래처 이력·후보 간 격차·LLM 판단을 함께 써야 한다 (설계 7-5와 일치)

## v5 — 매칭 해결 서브에이전트 resolver (2026-10-17)
- 가설: 정확 일치에 실패한 품목은 LLM이 검색·주문 이력·상품 상세를 조사하면 풀 수 있고, 점수 하나로 구분 못 하던 "진짜 애매" 케이스는 이력 기반 규칙으로 걸러낼 수 있다
- 변경: resolver 서브그래프(LLM ↔ 읽기 전용 도구 루프, 최대 5회), LLM 선택을 신호 규칙으로 최종 판정, 거래처 확인 상태(unclear_product) 추가
- 수치 (54건): decision 0.926 → **1.000**, 주문 완전 일치 0.915 → **1.000**, 자동 처리율 0.808 → 0.872, 오등록 0건 유지
  - 비용: 평균 토큰 1,169 → 2,048, 지연 2.8초 → 3.7초, $0.001 → $0.002 / 건
  - resolver 실행 품목 10개, 평균 도구 호출 2.8회(최대 3회)
  - "시럽"(messy_008): LLM이 스스로 ask_customer 판단 ("이 거래처는 바닐라·헤이즐넛을 모두 주문"). 규칙 안전장치는 발동하지 않음
  - "코카콜라": 검색어를 3번 바꿔 조회 후 not_carried
- 자동 처리율 0.872는 정답 라벨상 create인 비율과 같다. 즉 현재 평가셋에서는 상한에 도달

- 방법: 품목 단위 벤치마크 129개를 따로 만들고(`scripts/build_matching_bench.py`), resolver(LLM)는 한 번만 실행해 기록, 판정 정책은 오프라인 재생으로 비교(`evals/policy_sweep.py`)
  - 미등록 표현 91개: 같은 표현을 그 상품 이력이 있는 거래처 / 없는 거래처로 각각 평가
  - 일반 명칭 30개("시럽", "원두" 등): 거래처 이력에 해당 계열이 하나면 그 상품, 아니면 거래처 확인
  - 미취급 8개
  - LLM 실행 비용 $0.54, 70초 (8병렬)
- 결과 (오확정 = 틀린 상품으로 확정, 129개 기준)

| 정책 | 자동 확정 | 오확정 |
|---|---|---|
| 정확 일치만 | 0% | 0건 |
| 검색 1위 점수 ≥ 0.5 (LLM 없음) | 41% | 7건 |
| 검색 1위 점수 ≥ 0.6 (LLM 없음) | 17% | 0건 |
| LLM 판단만 | 84% | 7건 |
| LLM + 규칙 (이전 설정: 점수 차 0.15, 경쟁 gap 0.15) | 62% | 0건 |
| **LLM + 규칙 (현재: 점수 차 0.15, 경쟁 gap 0.1)** | **68%** | **0건** |
| LLM + 규칙 (점수 차 0.1, 경쟁 gap 0.1) | 74% | 0건 |
| LLM + 규칙 (이력 경쟁 검사 끔) | 71% | 2건 |

- 해석
  - LLM 판단만의 오확정 7건은 **모두 일반 명칭**("우유", "원두", "생크림"): 거래처가 주문한 적 없는(또는 여러 개 주문한) 상품을 "글자상 가장 가까운 것"으로 골랐다. 규칙이 7건 모두 막았다
  - 이력 경쟁 검사는 "원두"(이력에 원두 2종 이상) 오확정 2건을 막는다
  - 경쟁 gap 0.15는 과하게 보수적이었다: "녹차라떼 파우더"처럼 표현에 구분어가 있어도 이력의 다른 라떼 파우더와 점수가 가까우면 보류 → 0.1로 조정, 이력 있는 미등록 표현의 자동 확정 87% → 96%
- 운영 설정 선택: 점수 차 0.15 / 경쟁 gap 0.1
  - 점수 차 0.1이 자동 확정은 더 높지만(74%) 가장 가까운 오확정 사례("생크림" 1·2위 차 0.071)와의 여유가 0.029뿐이다. 0.15는 여유 0.079
  - 경쟁 gap 0.1과 가장 가까운 오확정 사례("원두" 0.054)의 여유는 0.046
  - 이 벤치마크로 고른 값이므로 같은 벤치마크 수치는 낙관적이다. 전체 평가 77건 재실행(v8)에서 회귀 없음 확인
- 라벨 주의: 달빛카페의 "생크림" → 식물성 휘핑크림(이력상 유일)은 논쟁 여지가 있다. 이력 하나를 근거로 정답 처리했다
